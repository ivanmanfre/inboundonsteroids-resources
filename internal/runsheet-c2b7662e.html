AI Orientation Session — Call Guide

$500 · 90 min. Follow top to bottom. Goal: get Derek running Claude Code himself, and build one real thing.

How this works: you direct, Derek drives — he types, you talk him through it. He almost never runs a command himself; he tells Claude what he wants in plain English and Claude does it.
Green = what Derek tells Claude Dark = type once Red = say out loud
0

Before the call

prep
  • Confirm his payment landed + he got the booking email (he did — delivered).
  • He should be at a laptop on Zoom (not his phone), tools open, with the one workflow eating his week + a sample doc handy.
  • Confirm he has a Claude Pro or Max plan — Claude Code won't run without one.
  • You: do a 10-min Ollama dry run on your own Mac first (install, pull an 8B model, chat once) so you're not learning it live.
1

Open the call

~10 min

Frame it: "We set up your tools, then build one real thing. You drive, I steer. After this you get a written plan."

Screen: he shares his screen and drives. In Zoom you can Request Remote Control to grab the keyboard for a tricky step — use it sparingly, he should be the one doing it.

Ask the two questions that decide everything:

  1. "Is the data you'd automate something you can't send to the cloud?" → decides Mac vs cloud.
  2. "What's the one job eating the most of your week?" → that's the first build.
Discovery: ask what he already uses. He mentioned "Hermes" (a premade agent) and "Claude Cowork" (a Claude tool) — find out what they are and what he uses them for, so you build on what he's got instead of duplicating it.
2

Install the tools

~10 min
  • Download VS Code from code.visualstudio.com and install it.
  • Inside VS Code, install the Claude Code extension and sign in to Claude.
Blocker check: no Claude Pro/Max plan = Claude Code won't run. Sort it before anything else.
3

Project, GitHub + CLAUDE.md

~15 min

Open his project folder in VS Code. From here it's all plain English. First, make it a private synced repo:

Turn this folder into a git repo, add a .gitignore that keeps my .env and API keys out, and push it to a new private GitHub repo called [name].

GitHub sign-in is not a command he learns. The first time Claude pushes, a browser pops up to sign into GitHub — he clicks approve. That one click is the only manual bit.

Fallback if Claude can't trigger the sign-in — type this once (it opens the same approve-popup):

gh auth login

Then give Claude a memory of his setup:

Write a CLAUDE.md for this project — my tools, how I work day to day, and the rules ("never do X"). Keep it short.

Read it together, fix anything wrong. This file is the highest-value thing — Claude reads it every session, so he never re-explains his setup.

4

Permissions (so Claude stops asking)

~8 min

By default Claude asks before every command — exhausting for a beginner. Fix it:

  • Type /permissions to see + edit what Claude can do on its own.
  • Allowlist his routine-safe commands so it stops asking (git, ollama, etc.).
  • Modes — press Shift+Tab to cycle: default (asks) → accept-edits (auto-approves edits, once he trusts it). Start on default.
Never turn on "bypass permissions" — that runs anything with no check.

He can just tell Claude to write the settings file:

Create a .claude/settings.json that allows my git and ollama commands and sets the model to opus.
5

Memory (it's automatic)

~4 min

Nothing to build. Claude Code remembers his project on its own (on by default). Type /memory to see it. Durable rules go in CLAUDE.md; the rest saves itself.

Say it: "You do NOT need a database or a memory system. Built-in is enough until you're way bigger." Telling him what not to build is half the value.
6

Skills + commands

~15 min
Clear the #1 confusion: you do not install a skill by telling Claude "install X." That does nothing. Skills come from the /plugin menu, or they're just files in a folder.

A. Install Superpowers (free pack)

/plugin marketplace add anthropics/claude-plugins-official /plugin install superpowers@claude-plugins-official

Adds disciplined workflows — planning, debugging, double-checking work.

B. Get my shared starter commands

My 4 stochastic commands, made generic. They live in my public repo. He pulls them in plain English:

Download the 4 command files from github.com/ivanmanfre/resources (folder starter-skills/.claude/commands) and copy them into this project's .claude/commands folder.

Now he has /stochastic-decision, /stochastic-research, /stochastic-audit, /stochastic-red-team. They're in his repo, so they sync to both his machines automatically.

For you, not him: never hand over your own business skills — recall, brain, negotiate, proposals, clickup-searcher, leverage-radar, n8n-execs. They're wired to your systems and they're your edge. Demo the idea, never the files.

C. Commands he'll use daily

  • /init — first time in a project: writes the CLAUDE.md for him.
  • Plan mode (Shift+Tab to "plan") — "plan it before you build." He reviews, then says go. Safest habit.
  • /clear — start fresh when he switches tasks.
  • /compact — shrink a long chat without losing the thread.

D. Tools for his stack

n8nac — a CLI that lets Claude manage his n8n workflows as code + look up node configs (so it doesn't guess). Worth it since he's building in n8n:

npm install -g n8nac

Also install:

  • deep-research — multi-source, fact-checked answers. Same /plugin marketplace as Superpowers.
  • Playwright (browser automation) — Claude opens sites, screenshots, scrapes (e.g. pull from regulatory portals). Add the Playwright MCP.
  • computer-control MCP — lets Claude actually drive his screen + clicks, for tasks with no API. He says "add the computer-control MCP." macOS will ask for screen + accessibility access — grant it. watch it the first few runs
7

Let Claude peek at Pipedrive + n8n

~10 min

Where it gets useful — let Claude read his real tools. He runs Pipedrive (CRM) and n8n. Each needs an API key: a one-time grab from the tool's settings, saved in his .env (git-ignored, never pushed).

Pipedrive (his CRM)

Get the key: Pipedrive → Settings → Personal preferences → API → copy the token. Then:

Save my Pipedrive API token in .env and use it to read my deals and leads.

Now he can ask: "Show me my hottest leads I haven't contacted yet."

n8n

Get the key: n8n → Settings → n8n API → create an API key. Then:

Save my n8n API key and URL in .env and use them to check my workflows.

Now: "What failed in n8n today?" · "Is [workflow] running right now?"

Keys go in .env — git-ignored, so they never reach GitHub. (Pipedrive + n8n both have MCP servers too, but the API-key route is the simplest to teach.)
8

The local model

~10 min

Only if Part 1 flagged private data. It's simpler than it sounds: install one app, download one model.

  1. Install Ollama from ollama.com (or say "install Ollama").
  2. Pull a model: ollama pull llama3.1:8b (or have Claude do it). 8B fits most Macs; the Studio runs bigger.
  3. It runs at localhost:11434 — the address n8n points to for private parsing.
Plain terms: Ollama is the engine; the model (Llama, Qwen…) is what it runs.
The routing rule: private or bulk work → the local model. Anything needing real thinking → Claude. Don't make the local model do the reasoning.
9

Both machines (Mac + PC)

~5 min

He doesn't choose a machine — the repo lives on both. Install the tools on each, then it's plain English:

Clone my private repo [name] and set it up here.
Pull my latest from GitHub.
Say out loud: secrets never go to GitHub (git-ignored) · the local model stays on the Mac · memory is per-machine, but CLAUDE.md syncs.
10

Build one real thing

~20 min

The part he remembers. Pick one — the rest is backlog. My pick is the daily brief: recurring value, and it shows off the whole stack.

A — Daily brief recommended

A workflow that messages him every morning with what needs him today.

The n8n flow: Schedule (7am) → pull Pipedrive (new + uncontacted leads, deals gone quiet) + n8n (overnight failures) + his site data (inspections due) → Claude summarizes → send.

Reads like: "3 new leads to chase · 1 deal gone quiet · 2 sites due for inspection · 0 automations failed."

Pick the channel + expand its steps (Derek has Slack):

Slack  his workspace
  1. Go to api.slack.com/apps → Create New App → From scratch → pick his workspace.
  2. Features → Incoming Webhooks → toggle On → Add New Webhook to Workspace → pick a channel → copy the Webhook URL.
  3. In n8n: use the Slack node (or an HTTP Request node) to post the brief to that Webhook URL.

Private DM instead of a channel? Use a bot token with the chat:write scope.

Telegram  simplest · phone push
  1. In Telegram, message @BotFather → /newbot → name it → copy the bot token.
  2. Message the new bot once (say hi). Get his chat ID from @userinfobot.
  3. In n8n: add the Telegram credential (paste token) → Telegram → Send Message node with his chat ID.
Email  no bot
  1. In n8n: add an email credential — SMTP (his email) or a service like Resend (API key).
  2. Use the Send Email node → to his address, subject "Morning Brief", body = Claude's summary.

B — Inspection-report parser

Field notes/PDFs → clean compliance fields. Best private + bulk payoff; runs on the local model.

C — Hottest untouched leads

Pull from Pipedrive, rank the un-contacted ones. Fast money win; runs on Claude.

★ Make Claude prove it: he can't read code, so he says — "test it end-to-end and show me the message it would send." That's how a non-dev trusts the output.
11

Optional: a live dashboard if hungry

bonus

If the build lands and there's appetite, the wow-moment is a simple always-on web page. Keep it to one useful number (e.g. "sites needing inspection this week" or "what ran / failed today").

Build a simple one-page web dashboard showing [the one number], and deploy it to Railway so it's always online at a link.

Claude builds it + walks him through deploying to Railway (free to start). One number, one page — don't over-scope.

12

The 5 habits + 3 traps

Drill these habits

  1. CLAUDE.md first — short and current.
  2. Plan before building — review, then go.
  3. Point at files — @filename, don't describe.
  4. Make it verify — "test it, show me."
  5. Commit often — checkpoints to roll back to.

Warn him off these traps

  • Kitchen-sink chat (10 tasks in one session → Claude loses the thread) → /clear between tasks.
  • Bloated CLAUDE.md (whole docs pasted → rules buried) → keep it tight.
  • Trusting without checking → always make it test/show.
13

Leave alone + close

What NOT to build (yet)

  • No database / "memory brain" — built-in memory is enough.
  • Don't force everything onto the local model — let Claude think.
  • Don't build all the skills at once — one working thing beats ten half-built.

His next steps this week

  • VS Code + Claude Code + his CLAUDE.md.
  • Ollama + a model on the Mac (if private data).
  • Finish the one build you started.
  • Watch for the written plan you'll send.
